# Hackathon Requirements Checklist

Source: `hackathon-brief.docx`. Build 2:00 to 5:45pm, code freeze 5:45pm, pitches from 6:15pm.

## 0. Setup (by 2:00pm)
- [ ] Track chosen and confirmed: 1 Opportunity Here / 2 Small Business, Big Tools / 3 Start Something
- [ ] Team of about 5, with roles: build, AI/backend, demo/UX, business case, deck/pitch
- [ ] No code written before 2:00pm (ideas are fine)

## 1. A real problem (Real-world fit, 30%, Richard Blakeborough)
- [ ] One specific user in the North East, named precisely (e.g. "owner of a 6-person Gateshead café", not "small businesses")
- [ ] One clear problem, solved well, not several solved badly
- [ ] Why they'd use it **next month**
- [ ] Tied to the regional context (744 vs 1,436 businesses per 10k adults; two-thirds of NE jobs are in small firms)
- [ ] Track "Think about" points handled:
  - Track 1: bias and fairness, paying people properly, who the design leaves out
  - Track 2: confident mistakes, sensitive data, people losing skills they still need
  - Track 3: bad advice with real costs, false encouragement, people without laptops, time or money

## 2. A working product (Technical quality, 40%, Dr. Kay Rogage)
- [ ] Live demo runs end to end
- [ ] Uses realistic input, with **no real people's personal data** (synthetic only)
- [ ] The AI does something the user couldn't easily do alone
- [ ] The team can explain how it works (architecture in one sentence)
- [ ] The team can explain where it fails, with known limits and safeguards
- [ ] The team can explain how they used AI, both in the product and in building it with Claude Code
- [ ] Rehearsed demo path, plus a backup (recorded video or screenshots) in case the wifi fails
- [ ] Code freeze respected at 5:45pm

## 3. A business (Investability 15% + Go-to-market 15%)
### Who pays (Owen Conquest)
- [ ] Main paying customer and why they'd pay **this year**
- [ ] Rough count of how many of them exist (market size)
- [ ] If the payer isn't the user, how you get both on board
- [ ] Why choose this over what already exists (competitors or the current workaround)
- [ ] Why this team can deliver it

### Financial viability (slide 4)
- [ ] Price
- [ ] Cost to serve one customer, **including AI/API costs**
- [ ] Number of customers needed to break even
- [ ] Monthly revenue and profit at 100 customers
- [ ] If the model pays people: at least minimum wage plus related costs
- [ ] Assumptions stated and believable

### First 100 customers (slide 5, Josh Sanghera)
- [ ] Who you'll target first
- [ ] Their problem and your offer
- [ ] Route in (channel), with target numbers
- [ ] Biggest risk and how you'd test it

## 4. Submission (by 5:45pm, one per team)
- [ ] Working prototype, ready to show live
- [ ] **Public** GitHub repo (this repo is currently private, so make it public before submitting)
- [ ] Pitch deck as PowerPoint **made from the template**: title slide plus up to 5 slides
  - [ ] Slide 4 = financial viability
  - [ ] Slide 5 = first 100 customers
- [ ] One paragraph covering the problem, the solution and who pays

## 5. Pitch (3 min hard stop + 2 min Q&A)
- [ ] Rehearsed to under 3 minutes with a timer
- [ ] Deck loads in advance, so be ready the moment you're called
- [ ] Every judge's criteria hit: demo (40), real user (30), who pays (15), first 100 (15)
- [ ] Q&A answers prepped: where it fails, data safety, competitors, cost assumptions

## Suggested timeline
| Time | Milestone |
|---|---|
| 2:00 | Problem, user and scope locked; repo and roles set |
| 3:00 | Core AI flow working on sample input |
| 4:00 | End-to-end demo working; business numbers drafted |
| 4:45 | Feature freeze; polish, backup recording, deck filled |
| 5:15 | Repo public, README updated, paragraph written |
| 5:45 | Submitted |
| 6:00 | Final pitch rehearsal |
